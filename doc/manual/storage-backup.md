# 存储、快照与备份

「存储」用于浏览内容；「数据中心 → 存储」管理存储定义。添加一个存储定义与上传一个镜像是两种不同操作。

## 浏览与上传

打开存储后，先检查所属节点、容量和内容类型。只有支持相应内容类型的存储，才会提供 ISO、容器模板、备份等对应入口。

- **上传**：把电脑或手机上的文件发送到所选存储，保持页面与网络可用直到上传结束。
- **从 URL 下载**：由 PVE 下载文件，PVE 主机本身必须能访问该地址。
- **容器模板目录**：从可用模板列表选择并下载，再用于创建容器。

删除文件、卷或备份前，核对是否仍被客户机使用以及是否需要保留。存储页面的内容与操作会根据存储类型和权限变化。

## 快照和备份有什么区别

| 项目 | 快照 | 备份 |
| --- | --- | --- |
| 常用目的 | 配置变更前保留短期回退点 | 保存可恢复的客户机副本 |
| 所在位置 | 通常依赖当前客户机的存储 | 写入指定的备份存储 |
| 主要限制 | 受客户机磁盘格式和存储能力限制 | 需要足够空间与备份时间 |
| 恢复方式 | 回滚快照 | 从备份恢复客户机 |

快照通常不能防止底层存储故障。重要数据应保存在合适的备份目标，并验证可以恢复。

## 创建与回滚快照

1. 打开客户机的「快照」标签。
2. 创建快照，填写名称和说明；是否包含内存由当前类型和界面支持决定。
3. 等待任务结束，确认快照出现在列表或树中。

回滚会恢复到快照时的状态，之后的改动可能丢失。先确认快照时间与目标客户机，必要时为当前状态另做备份。

## 立即备份

在客户机的「备份」页选择立即备份，指定备份存储、模式等参数后提交。模式可能影响客户机运行状态和备份一致性，按照窗口说明选择。

任务结束后，在备份列表核对客户机 ID、时间和结果。仅看到「任务已创建」并不能说明备份成功。

## 恢复备份

从客户机的备份列表或存储中的备份文件打开恢复窗口，确认目标 ID、存储和启动选项。

::: warning 核对恢复目标
恢复到已有 ID 可能覆盖现有客户机。需要检查备份内容时，优先使用空闲 ID，并提前处理网络地址冲突，避免副本与原客户机同时使用同一地址。
:::

恢复后检查系统启动、数据和网络。支持文件级恢复的存储与备份，可使用对应入口查看或提取文件。

## 计划备份与保留策略

在「数据中心 → 备份」配置周期任务，核对节点、客户机选择范围、存储、时间计划和保留策略。使用计划模拟等入口检查实际触发时间。

保留策略可能清理旧备份，保存前检查需要保留的恢复点。定期查看失败任务与未覆盖的客户机，避免新建资源后没有加入备份范围。
