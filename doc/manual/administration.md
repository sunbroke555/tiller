# 节点与数据中心

节点页面处理某一台 PVE 主机；数据中心页面管理集群共享配置。修改前先确认当前所在层级。

## 节点页面

| 区域 | 主要用途 |
| --- | --- |
| 概要、客户机 | 查看节点状态、资源曲线与本节点客户机 |
| Shell、系统日志、服务 | 排查系统问题，查看日志，管理服务 |
| 网络、系统 | 配置网卡、网桥、DNS、Hosts、时区等 |
| 磁盘 | 查看物理盘与 SMART，管理支持的存储布局 |
| 更新、证书 | 查看软件更新、软件源以及节点证书 |

修改网络后可能出现待应用配置。先检查差异，确认管理地址仍可达，再执行应用；最好保留独立的控制台访问方式。

初始化、擦除磁盘和销毁存储会影响数据。根据磁盘标识、容量和用途确认目标，不能仅按列表顺序判断。

### 硬件监控

接入入口会说明采集组件、磁盘检查频率与 UPS 读取范围。点击 **一键接入** 后，进度窗口实时显示检测服务、安装或复用软件包、启动任务和验证连接的日志。可以收起窗口并通过 **操作日志** 再次打开；请保持当前页面打开。完成后窗口保留结果，失败时可查看失败步骤并重试，日志不包含安装密码或凭据。

节点默认 Shell 为 zsh 时也可接入：Tiller 在操作会话中启动独立 Bash，不更改节点的默认 Shell。失败窗口会显示失败步骤、原因、处理建议和执行状态，并支持复制诊断信息；未识别的错误会明确说明原因尚未确认。若连接在节点执行过程中中断，部分步骤可能已经完成，应先检查当前状态后再重试。

在 **节点 → 系统 → 硬件监控** 点击 **一键接入**。Tiller 会检测节点管理地址上的 node_exporter；没有可用服务时，如果实例已通过 `root@pam` 账号密码连接，会沿用现有授权直接安装。其他连接方式会弹窗请求一次 PVE `root@pam` 密码，支持 TOTP 二次验证；弹窗中的密码只用于本次授权，不会保存。此过程无需 SSH，也不会修改 PVE 的 JS 或 Perl 文件。

接入后，**节点 → 概要** 展示硬件状态：温度、风扇、CPU 封装功耗与频率、电源/UPS，以及自动采集的磁盘 SMART。读不到的指标显示不可用。虚拟化的 PVE 节点通常不会暴露宿主机的物理传感器。

- 温度、风扇和频率来自内核接口，不要求安装 lm-sensors 或 turbostat。CPU 功耗取两次 RAPL 能耗计数器的差值，首次显示需等待约 30 秒；它不是整机墙上插座功耗。
- 传感器在页面可见时每 30 秒刷新，共享服务端缓存。node_exporter 常驻，Tiller 离开页面后停止请求；如果另有监控程序访问 exporter，它仍会按那些请求采集。
- SMART 在节点后台每 10 分钟采集一次，浏览器未打开时也会更新。页面及 **刷新显示** 按钮只读取缓存，不会额外查询硬盘。缓存放在 `/run` 内存文件系统中，不为记录监控数据而写入硬盘；重启后重新建立缓存。
- 自动采集支持直接连接的 SATA/ATA 与 NVMe。ATA 使用指定设备类型和 `smartctl -n standby,3,5`，休眠或不支持电源状态检查时停止读取，不尝试强制唤醒。休眠盘保留上次数据及原始时间；无法安全判断的 USB、SAS、RAID 映射等设备保守跳过，可通过原有磁盘页面查看。Tiller 不执行自检、介质扫描或写盘测试。
- UPS 支持系统电池信息，以及同一节点上已经运行并允许读取的 NUT 服务（3493 端口）。目前读取第一个 UPS；不会自动安装或改动 UPS 驱动与关机策略。独立网络 UPS、IPMI 和历史硬件曲线尚未接入。

自动安装使用 Debian 的 `prometheus-node-exporter` 包和独立的 `tiller-node-exporter.service`，通过 19100 端口提供带认证的 TLS 服务；Tiller 固定校验服务证书。节点防火墙需要允许 Tiller 到该端口。复用已有服务时检测 9100 端口，并仅请求硬件相关采集器。

自动 SMART 通过 `tiller-smart-collector.timer` 定时运行一个短时采集任务，使用 Python 3 和 smartmontools，缺少时由一键接入补齐；结果交给 node_exporter 的 textfile collector。旧版接入可以在 **系统 → 硬件监控** 点击 **启用自动 SMART** 升级，无需手工配置。升级前仍保留原有手动读取方式。

NVMe 温度优先按设备上报的警告、严重阈值变色。悬停温度可查看具体阈值，以及它来自设备、推算还是默认提醒值。两档均未提供时，默认在 70°C 提醒、80°C 标红；这些默认值不代表所有型号的温度上限。已启用自动 SMART 的旧采集服务会显示 **更新采集服务**，更新后等待下一次后台采集即可使用设备阈值。

**停止采集** 会停止 Tiller 创建的采集服务、SMART 定时器和正在执行的 SMART 任务，并关闭开机自启。配置和软件包保留；点击 **恢复采集** 即可恢复，无需重新安装。必要时会请求一次节点管理员授权。复用外部 node_exporter 时，仅断开 Tiller 读取，不管理外部服务。

**卸载服务** 会先检查安装记录和软件包依赖，再移除 Tiller 创建的服务、配置、缓存和本次接入新增的软件包。若需要连带移除其他软件包，则提示依赖冲突并取消卸载。系统原有的软件包与 `smartd` 保持原状；旧版缺少安装记录的软件包会提示并保留。

监控连接保存在实例配置旁的 `.hardware.json` 文件中，采集凭据加密保存；迁移时请连同实例配置、管理员配置及其 `.key` 文件一起备份。

## 数据中心页面

| 区域 | 主要用途 |
| --- | --- |
| 集群 | 查看节点与集群连接，创建或加入集群 |
| 存储 | 管理共享的存储定义和节点适用范围 |
| 备份、复制 | 安排备份任务和存储复制 |
| 权限 | 管理用户、组、角色、ACL、认证域和资源池 |
| 防火墙 | 管理各层级规则、安全组、地址集合和日志 |
| HA | 管理高可用资源、状态和亲和规则 |
| SDN、Ceph | 管理已规划的软件定义网络和分布式存储 |
| 通知、指标 | 配置通知目标、匹配规则和外部指标服务 |
| 资源映射、选项 | 管理跨节点设备映射以及数据中心行为 |

这些入口受 PVE 版本与权限影响，打开某个页面不代表相关服务已经安装或启用。

## 保存与应用

网络、SDN 等配置可能先保存为待应用状态，再由单独的应用操作生效。保存后先看页面提示与差异，不要仅根据表单关闭就判断运行配置已改变。

HA、集群加入和存储销毁等操作会影响多台客户机或节点。执行前确认 PVE 环境已经具备相应条件，并阅读确认窗口。

## 查看操作结果

有任务标识的操作，进入[任务日志](console-tasks.md)查看最终结果。涉及集群配置时，再检查受影响节点与资源的状态。
