# 虚拟机与容器

在概览、资源池或资源树中打开客户机。标题里的节点、类型和 ID 用来确认操作对象：VM 是 QEMU 虚拟机，CT 是 LXC 容器。

## 查看状态与执行电源操作

概要页显示运行状态、CPU、内存、磁盘和网络等信息；IP 等部分信息取决于客户机和 Guest Agent 是否提供数据。

| 操作 | 使用场景 |
| --- | --- |
| 启动 | 启动已停止的客户机 |
| 关机 | 请求客户机正常关闭，通常优先使用 |
| 停止 | 强制停止，未保存的数据可能丢失 |
| 重启 | 请求客户机重新启动 |
| 重置 | 强制重置虚拟机，类似断电后立即开机 |
| 挂起 / 恢复 | 暂停或恢复支持该操作的客户机 |

可用操作随类型、状态和权限变化。点击后如果出现任务提示，打开日志确认结果。

## 修改虚拟机配置

虚拟机的「硬件」页管理 CPU、内存、磁盘、网络和其他设备；「选项」页管理启动等行为；「Cloud-Init」页用于已配置 Cloud-Init 的模板或镜像。

1. 进入对应标签，选择要修改的项目。
2. 在表单中检查当前值与目标值，保存。
3. 查看是否出现待生效的配置。有些修改需要完整关机后再启动，具体以页面和 PVE 提示为准。

不要把重启操作系统与关闭后重新启动虚拟机视为同一件事。磁盘扩容后，客户机里的分区和文件系统可能仍需另外扩展。

## 修改容器配置

容器的「资源」页管理 CPU、内存、交换空间、根盘和挂载点；网络、DNS 与选项分别在对应标签中。

挂载点可能引用独立存储或宿主机路径。删除、移动或调整挂载点前，检查其中的数据以及是否包含在备份中。

## 创建客户机

从界面中的创建入口选择虚拟机或容器，按向导指定节点、ID、存储、网络和其他配置。创建虚拟机前通常先准备 ISO，创建容器前先准备模板，见[存储说明](storage-backup.md)。

提交后跟踪创建任务。创建完成并不一定代表操作系统安装完成；虚拟机可能仍需在控制台里完成安装。

## 克隆、迁移与模板

- **克隆**会创建另一个客户机，提交前核对新的 ID、名称和目标存储。
- **迁移**会把客户机迁往其他节点，需要满足目标资源、存储和网络条件。
- **转为模板**用于后续重复创建；先确认这台客户机不再按普通实例使用。

批量操作同样作用于真实资源。先核对选择列表和目标节点，再提交，并逐项查看任务结果。

## 删除与保护

删除客户机可能同时删除关联磁盘。确认窗口会要求核对对象；不要仅凭名称相似就继续。需要保留数据时，先完成可恢复的备份。

保护设置可以限制部分误操作，但不代替备份。快照、立即备份和恢复见[下一章](storage-backup.md)。
