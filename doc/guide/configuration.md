# 连接与安全配置

Tiller 的监听和数据文件位置通过环境变量配置，修改后需要重启进程。PVE 连接在「实例管理」页面维护，保存后立即生效。「外观与偏好」只影响当前设备。

## 两段连接

```text
浏览器 ── HTTPS ── Tiller ── HTTPS ── Proxmox VE
                   /docs/            :8006
```

浏览器到 Tiller 的证书与 Tiller 到 PVE 的证书分别配置。浏览器显示安全锁，并不代表上游 PVE 的证书已经正确校验。

## PVE 地址与证书

| 环境变量 | 用途 |
| --- | --- |
| `PVE_URL` | 可选的初始 PVE 地址，只填协议、主机和端口；不设置时从页面添加连接 |
| `PVE_TLS_FINGERPRINT` | 固定信任 PVE 叶子证书的 SHA-256 指纹，接受冒号分隔或纯十六进制形式 |
| `PVE_CA_FILE` | 部署的 CA 信任链；未固定指纹的连接使用它校验服务器证书 |
| `PVE_INSECURE_TLS=1` | 跳过 PVE 证书校验，仅用于实验环境；不能与固定指纹同时使用 |

可以在 PVE 的证书页面查看证书，或在 PVE 主机上执行 `pvenode cert info` 核对指纹。不要使用未经核对的证书指纹。PVE 证书更换后，固定指纹也需要更新。

不设置指纹或自定义 CA 时，Tiller 按系统信任链验证 PVE 证书。自签名证书通常需要固定指纹或提供 CA 文件。

## 多实例连接

Tiller 登录与 PVE 连接分开管理：先设置并登录 Tiller 管理员，再添加各 PVE 的地址和登录凭据。所有实例都可在页面编辑或删除，最多保存 64 个连接。

1. 在「实例管理」点击「添加实例」，填写名称和 HTTPS 地址。默认选择「账号密码」，输入 PVE 用户名、认证域和密码；保存前会验证登录。
2. 也可选择「API Token」，填写完整 Token ID（例如 `tiller@pve!tiller`）和 Token Secret。启用权限分离时，还需要给 Token 自身分配权限；有效权限受 Token 和所属用户共同限制。
3. 自签名证书建议填写 SHA-256 指纹。不填时使用系统或部署指定的 CA 信任链；仅实验环境可以跳过证书校验。
4. 保存后进入实例，电脑侧边栏会分别显示每个实例的节点和资源。同一集群只需添加一次。

资源树中展开的其他实例每 10 秒独立刷新，折叠后暂停资源轮询。连接异常或凭据未配置会在对应实例分支提示，不影响浏览其他实例。资源树支持按名称、VMID、节点和实例名称过滤；每个实例只显示其 PVE 用户或 Token 有权读取的资源。

实例的页面 URL、API、控制台和资源相关偏好按连接隔离。更改地址、证书设置、认证方式或账户时，需要重新填写 PVE 密码或 Token Secret；更改连接或凭据会生成新连接版本，旧链接提示重新选择。仅修改名称可保留原凭据。已保存的密码和密钥不会回显，删除连接不会删除 PVE 资源，也不会自动吊销 PVE 上的 Token。

| 环境变量 | 用途 |
| --- | --- |
| `TILLER_AUTH_FILE` | 管理员配置文件，默认 `tiller-auth.json`，相对于进程工作目录 |
| `TILLER_INSTANCES_FILE` | 实例配置文件，默认 `tiller-instances.json`，相对于进程工作目录 |
| `PVE_NAME` | 首次从 `PVE_URL` 导入连接时的名称，默认「默认 PVE」 |

新部署可以不设置 `PVE_URL`，登录后从页面添加全部连接。首次启动时若显式设置了 `PVE_URL` 且没有实例配置文件，会导入一个待配置登录凭据的连接。已有实例配置优先，后续连接修改在页面完成。

管理员密码采用带随机盐的 PBKDF2-HMAC-SHA256（600,000 次迭代）保存。PVE 密码和 Token Secret 使用 AES-256-GCM 加密，密钥位于 `TILLER_AUTH_FILE` 同路径加 `.key` 的文件中。三个文件均为 `0600`，目录需可写；一个数据目录由一个 Tiller 进程使用。备份时同时保留管理员文件、`.key` 和实例配置文件，丢失密钥无法解密已保存凭据。仓库 Compose 示例把这些文件放在 `tiller-data` 卷中。

## 忘记管理员密码

在服务器上停止 Tiller，备份数据后移走 `TILLER_AUTH_FILE` 指定的管理员 JSON 文件，**保留对应的 `.key` 和实例文件**。重新启动后可再次设置管理员。应在受控访问范围内完成设置，完成前不要对外开放服务。重置后已有连接凭据保留，所有旧会话失效。

## Tiller 的监听与 HTTPS

| 环境变量 | 用途 |
| --- | --- |
| `LISTEN` | 监听地址，默认 `:8080`。同机反向代理可用 `127.0.0.1:8080` |
| `TLS_CERT_FILE` | Tiller HTTPS 证书文件，与私钥一起设置 |
| `TLS_KEY_FILE` | Tiller HTTPS 私钥文件 |
| `WEB_DIR` | 从指定磁盘目录提供前端与文档，主要用于调试；通常使用二进制内嵌版本即可 |

手机添加到主屏幕等浏览器能力需要安全上下文。使用客户端信任的 HTTPS 地址，避免靠忽略证书错误长期访问。

## 访问范围与反向代理

| 环境变量 | 用途 |
| --- | --- |
| `ALLOW_FROM` | 允许访问的客户端 IP 或网段，逗号分隔，例如 `192.168.1.0/24,10.8.0.5`；本机地址总是允许 |
| `TRUSTED_PROXIES` | 信任哪些代理发来的 `X-Forwarded-For`，填写代理的 IP 或网段 |

只把实际使用的代理加入 `TRUSTED_PROXIES`，这样登录限速和日志才能识别真实客户端地址。`ALLOW_FROM` 也适用于文档；无需登录不代表绕过实例的访问限制。

Tiller 向 PVE 转发 `X-Forwarded-For`。如果需要在 pveproxy 访问日志里查看真实客户端地址，可按 PVE 的配置设置 `PROXY_REAL_IP_HEADER` 和 `PROXY_REAL_IP_ALLOW_FROM`。pveproxy 的访问控制仍可能只看到 Tiller 的地址，应在 Tiller 上配置客户端范围。

## 登录信息如何处理

Tiller 管理员会话使用 HttpOnly、SameSite=Strict 的 Cookie；写请求校验 CSRF token，WebSocket 校验来源。登录失败会触发限速。会话最长 8 小时，重启服务或修改管理员密码后需重新登录。

服务端仅向选中的 PVE 注入该实例的票据和 PVE CSRF token，或 API Token，不会转发 Tiller 管理员 Cookie、密码或 CSRF token。账号密码连接在请求时自动续期；票据过期后使用已加密保存的 PVE 密码重新登录。重启后也能自动恢复 PVE 连接，无需再次填写凭据。

PVE 密码被更改、账户被禁用或 Token 被撤销时，对应实例显示连接异常，不会退出 Tiller 或影响其他实例。更新连接里的凭据即可恢复。失败认证会退避重试，避免轮询持续提交错误密码。写操作失败时不自动重放，需确认后重新提交。

账号密码连接当前不保存两步验证种子，也不支持需要交互的 PVE 两步验证或 OpenID 登录；这类账户请选择 API Token。PVE 上的权限仍限制可执行操作，Tiller 管理员不会绕过这些限制。
